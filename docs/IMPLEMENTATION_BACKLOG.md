# e-Class MCP 구현 목록

## 자료 선택 및 다운로드 추상화

상태: 제안 / 구현 대기

### 목적

에이전트가 자료 조회 결과의 URL과 다운로드 관련 필드를 수동으로 재구성하면서 누락하는 문제를 방지한다. 에이전트는 자료 선택을 담당하고, MCP는 메타데이터 보관·선택 해석·다운로드 경로 구성·실패 복구를 담당한다. 링크 유효성 사전 검사는 추가하지 않는다.

### 인터페이스

- [ ] `eclass_get_materials` 조회 결과를 서버에 저장하고 고유한 `list_key`를 반환한다.
- [ ] 응답의 각 자료에 목록 내 고정 번호 `no`를 부여한다. 제목, 주차, 파일 종류, 다운로드 가능 여부, 캐시 여부를 선택 정보로 제공한다.
- [ ] 내부에는 원본 자료 객체의 ID, URL, ExternalTool URL, source, LTI 런치 표시, 분류 및 잠금 정보를 보존한다.
- [ ] 다운로드 도구에 `list_key`와 `select`를 받는 선택 계층을 추가한다. 기존 다운로드 엔진은 재사용한다.
- [ ] `select`는 `numbers`, `query`, `all_downloadable_pdfs` 중 정확히 하나를 허용한다.
- [ ] 캐시 재사용 및 목적지 충돌 정책을 선택 조건과 분리한다. backfill에서는 기존 파일 덮어쓰기를 허용하지 않는다.

요청 예시:

```json
{"list_key":"materials_abc123","select":{"numbers":[1,2]}}
```

```json
{"list_key":"materials_abc123","select":{"query":"수의체계"}}
```

```json
{"list_key":"materials_abc123","select":{"all_downloadable_pdfs":true},"reuse_cached":true,"on_conflict":"skip"}
```

필드명은 제안이며 기존 도구와의 호환성을 검토한 뒤 확정한다.

### 목록 저장 및 범위

- [ ] SQLite에 `list_key`, `course_id`, 생성·만료 시각, `materials_json`을 저장한다. TTL과 정리 정책은 구현 시 확정한다.
- [ ] 이미 반환한 목록과 번호는 변경하지 않는다. 재조회는 새 `list_key`를 생성한다.
- [ ] 목록은 인증 계정 범위에 귀속시킨다. 목록 키만으로 다른 계정의 자료에 접근하지 못하게 한다.
- [ ] 여러 강좌와 동시 요청에서 '마지막 목록' 같은 전역 암묵적 상태를 사용하지 않는다.
- [ ] 실행 시 최신 로컬 캐시 상태를 확인한다. 조회 당시 `cached` 값은 참고 정보로 취급한다.

### 선택 오류와 복구

| 상황 | 응답 및 처리 |
|---|---|
| 목록 조회 없이 번호 선택 | `LIST_REQUIRED`; 목록 조회를 안내하고 다운로드하지 않음 |
| 존재하지 않는 목록 키 | `LIST_NOT_FOUND`; 재조회 안내 |
| 만료된 목록 | `LIST_EXPIRED`; 재조회 안내 |
| 범위를 벗어난 번호 | `INVALID_SELECTION`; 유효한 번호 제공 |
| 키워드 일치 없음 | `NO_MATCH`; 선택 수정 안내 |
| 키워드 다중 일치 | `AMBIGUOUS_SELECTION`; 후보 번호와 제목 제공 |
| 잠금·다운로드 제외 항목 | 항목별 제외 사유 반환, 실행 가능한 나머지는 계속 처리 |
| 선택 방식 누락 또는 복수 지정 | 입력 검증 오류 반환 |

- [ ] 번호 요청에서 목록이 없다고 임의로 새 목록을 만들고 같은 번호를 실행하지 않는다.
- [ ] 키워드는 우선 제목 부분 일치로 구현한다. 다중 일치 전체 실행은 명시적인 옵션을 추가할 때만 허용한다.
- [ ] 강좌가 지정된 '다운로드 가능한 PDF 전부' 요청은 목록을 내부 조회해 실행할 수 있도록 별도 편의 인터페이스를 검토한다. 번호 선택과 구분한다.
- [ ] 오류 응답에 안정적인 `error_code`, 설명, 구조화된 `next_action`을 제공한다.
- [ ] `next_action`은 복구 안내이며 자동 실행 명령으로 취급하지 않는다.

### 다운로드 fallback

- [ ] 선택 번호를 실제 자료 ID로 변환한 뒤 기존 다운로드 로직에 원본 메타데이터를 전달한다.
- [ ] 로컬 캐시 파일이 실제로 존재하고 사용 가능한 경우 재사용한다.
- [ ] 캐시 기록만 있고 파일이 없으면 캐시 누락으로 처리하고 원본 다운로드를 시도한다.
- [ ] 실제 다운로드 접근 실패 시 해당 자료의 메타데이터를 갱신하고 지원되는 대체 경로를 시도한다.
- [ ] 갱신·fallback 동안 같은 실제 자료 ID를 유지한다. 새 목록의 같은 번호나 다른 파일로 대체하지 않는다.
- [ ] 메타데이터 누락은 `MATERIAL_METADATA_MISSING`으로 분리한다. 동일 인자로 backoff 재시도를 안내하지 않는다.
- [ ] 네트워크 일시 오류만 제한된 재시도 대상으로 분류한다. 재시도 횟수·시간 제한을 정한다.
- [ ] 부분 성공을 지원하고 자료별 성공, 캐시 재사용, 제외, 실패 및 사용 경로를 반환한다.
- [ ] 링크 유효성 사전 접속은 수행하지 않는다. 실제 다운로드 실패를 기준으로 복구한다.

### 저장 경로 및 기존 파일 보호

- [ ] 목적지 경로의 존재 여부, 디렉터리 여부, 쓰기 가능 여부를 확인한다.
- [ ] 목적지가 없으면 명시된 경로 생성 정책에 따라 처리한다. 쓰기 불가하거나 파일을 디렉터리로 지정한 경우 `DESTINATION_UNAVAILABLE`을 반환한다.
- [ ] 목적지 실패 시 임의의 다른 폴더로 저장하지 않는다.
- [ ] 기존 동일 이름 파일을 덮어쓰지 않는 충돌 정책을 다운로드·최종 배치 단계에 적용한다.
- [ ] 이름이 같다는 이유만으로 동일 자료라고 판정하지 않는다. 기존 자료 ID·해시 등 확인 가능한 근거를 사용한다.
- [ ] 중복 판단과 파일 충돌 결과를 응답에 명시한다.

### 도구 설명 보강

이행 기간에 기존 메타데이터 인자 방식도 유지한다면 다음 호출 규칙을 다운로드 도구 설명 앞부분에 추가한다.

> Build download requests directly from the material objects returned by `eclass_get_materials`. Map `id` to `file_id` and `title` to `display_name`. Preserve all returned download-routing fields, especially `url`, `external_url`, and LTI launch flags, along with classification and lock fields. Do not reconstruct requests from IDs and titles alone. If required routing metadata is missing, refresh or resolve the material instead of retrying the same request.

### 완료 기준

- [ ] 조회 → 번호 선택 → 다운로드가 URL을 에이전트에서 재조합하지 않고 동작한다.
- [ ] 조회 없이 번호를 요청해도 파일 다운로드가 발생하지 않는다.
- [ ] 재조회·동시 강좌 조회에도 기존 목록 번호의 의미가 유지된다.
- [ ] 키워드 모호성, 만료 목록, 잘못된 번호의 복구 응답을 검증한다.
- [ ] 캐시 파일 누락 및 다운로드 접근 실패의 fallback을 검증한다.
- [ ] 메타데이터 누락과 일시적 네트워크 오류의 재시도 처리가 구분된다.
- [ ] 기존 파일 충돌과 쓰기 불가 목적지에서 덮어쓰기·임의 경로 변경이 발생하지 않는다.
- [ ] 부분 실패 결과와 PDF 전용 선택에서 영상·잠금 항목 제외를 검증한다.

### 에이전트용 설명·스킬·문서 동기화

아래 항목은 e-Class MCP 저장소의 설명과 스킬에만 적용한다. 외부 파일 정리 스킬은 이 작업의 범위에 포함하지 않는다.

- [ ] `src/server.ts`: 조회·다운로드 도구의 설명과 입력·출력 스키마에 목록 선택 계약을 반영한다. `list_key`, 선택 방식, 캐시 정책, 오류별 다음 행동을 명시한다.
- [ ] `skills/eclass-cau/SKILL.md`: 강좌 확인 → 자료 목록 조회 → 목록에 연결된 선택 → 다운로드 결과 확인 흐름을 안내한다. 번호만으로 다운로드하거나 마지막 조회 목록을 추측하지 않도록 명시한다.
- [ ] `skills/eclass-cau/references/flows.md`: 번호·키워드·PDF 전체 선택과 목록 누락·만료 시 복구 호출 예시를 추가한다.
- [ ] `skills/eclass-cau/references/io-contracts.md`: 새 목록 선택 계약과 기존 메타데이터 인자 계약을 구분한다. 이행 기간의 지원 범위와 필드 보존 규칙을 명시한다.
- [ ] `skills/eclass-cau/references/troubleshooting.md`: 목록 누락·만료, 잘못된 번호, 키워드 모호성, 메타데이터 누락, 캐시 파일 누락, 다운로드 fallback 및 목적지 오류를 구분해 안내한다.
- [ ] `docs/TOOLS.md`: 새 인터페이스, 요청·응답 예시, 오류 코드, 기존 호출 방식의 호환 정책을 반영한다.
- [ ] `README.md` 및 다운로드 관련 문서의 호출 예시를 검색해 기존 계약과 충돌하는 설명을 수정한다. 해당 내용이 있는 문서만 변경한다.
- [ ] `scripts/install-skill.mjs`의 설치 경로와 갱신 동작을 확인한다. 저장소 원본·배포 패키지·설치된 e-Class 스킬의 동기화 절차를 정하고, 실제 설치본 갱신은 구현 배포 범위에 따라 수행한다.
- [ ] 실행 중인 MCP가 실제로 노출하는 도구 설명·스키마를 확인한다. 소스 수정만으로 반영됐다고 판단하지 않는다.
- [ ] 완료 검증에 도구 설명·스킬·참조 문서·예제의 호출 계약 일치 여부와 배포된 설명의 반영 여부를 포함한다. 설치본을 갱신하지 않았다면 미반영 상태를 명시한다.

### 구현 순서

1. 목록 저장 및 `list_key`/`no` 응답 추가.
2. 선택 해석·입력 검증 계층과 번호 기반 다운로드 추가.
3. 캐시 재사용·메타데이터 보충·오류 코드 정리.
4. 다운로드 실패 fallback 및 목적지 충돌 처리.
5. 키워드 및 PDF 전체 선택, 호환성 검증.
6. e-Class MCP 도구 설명·스킬·참조 문서·예제 동기화 및 배포 반영 확인. 각 구현 단계에서 관련 설명도 함께 갱신하고 마지막에 전체 일관성을 확인한다.

이 문서는 구현 계획이며 MCP 코드 변경이나 실제 다운로드를 수행한 기록은 아니다.
